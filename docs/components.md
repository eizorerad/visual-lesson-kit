## 1. Сцена и постоянные объекты

```js
D.deck.register({
  id: 'my-example',
  chapter: 'Тема',
  title: 'Один вопрос эпизода',
  notes: [F.note('Начальное состояние'), F.note('После первого шага')],
  build(ctx) {
    const v = F.stage(ctx, 'Один вопрос эпизода', 'Тема', 'Статус данных');
    const stage = K.viewport(v.svg);
    const state = { move: 0 };
    const point = F.dot(stage, 300, 350, 8, C.white);
    function paint() { F.pos(point, F.lerp(300, 900, state.move), 350); }
    paint();
    F.step(ctx, v, state, { move: 1 }, paint, 'Что именно изменилось.', 1800);
    return v.root;
  }
});
```

Заметок должно быть ровно на одну больше, чем вызовов `ctx.step`/`F.step`. Создавайте наблюдения в `build()` один раз, а внутри `paint()` меняйте координаты, размеры и видимость существующих узлов. Смена набора измерений — отдельный переход с явной подписью, а не незаметная мутация объекта.

Основные примитивы:

| API | Назначение |
|---|---|
| `F.group(parent)` | Постоянная группа SVG |
| `F.label(parent,x,y,text,size,color,anchor)` | Текст; горизонтальный anchor и вертикальный baseline по умолчанию `middle`, y — середина строки |
| `F.line(...)`, `F.seg(line,...)` | Создание и изменение отрезка |
| `F.dot(...)`, `F.pos(dot,x,y)` | Создание и перемещение отметки |
| `F.cell(parent,x,y,r,color,id)` | Учебная клетка; возвращает `g`, `membrane`, `nucleus` |
| `F.path(parent,points,color,width)` | Ломаная/путь; для morph меняйте `d` того же узла |
| `F.at(group,x,y)`, `F.opacity(node,t)` | Положение и видимость группы |
| `F.phase(t,start=0,end=1)` | Ограниченный 0…1 smoothstep на заданном интервале прогресса |
| `F.revealStroke(node,t)` | Раскрытие SVG-штриха без замены узла; при t=1 восстановлены исходные dash/pathLength |
| `F.growArrow(arrow,x1,y1,x2,y2,t)` | Рост существующей стрелки от постоянного начала к заданному концу |
| `F.tween(state,patch,paint,duration)` | Непрерывное изменение числового состояния |
| `F.driver(state,paint)` | Контроллер `set` / `to` / `cancel` / `dispose`; `to(patch,{duration,ease,after})` поддерживает линейные часы рассказа |
| `ctx.onDispose(fn)` | Освобождение ресурсов при смене или перестроении сцены |
| `F.step(ctx,v,state,patch,paint,caption,duration)` | Регистрирует один шаг проигрывателя |
| `T.evidence(root,options)` | Модальное окно полного источника и пояснения |
| `D.i18n.pack(lang,definition)` | Дополняет словари, заметки и QA языка; полные динамические шаблоны добавляются по порядку |
| `D.i18n.apply(root)` / `observe(root)` | Перевод существующих текстовых узлов и подписей; `observe` возвращает отключение |
| `D.i18n.onChange(fn)` | Подписка с отпиской; дополнительные подписки сцены освобождаются через `ctx.onDispose` |

В `01-objects.js` восемь RNA-знаков становятся восемью участками плоского столбика. Затем увеличиваются столбик и деления шкалы при неизменном значении. Редактируемые константы — `COUNT`, `UNIT`. Подписи и заметки также должны соответствовать новым данным. Концы количественных отрезков плоские: `stroke-linecap="butt"`.

## 2. Числовая шкала

```js
const y = K.linearScale([0, 10], [516, 236]);
y(5);        // 376
y.invert(376); // 5
```

Аргументы — две конечные различные границы domain и range. Обратное направление range допустимо: большее значение можно расположить выше. По умолчанию шкала экстраполирует; `{clamp:true}` явно ограничивает результат границами. Числовые ошибки не превращаются в нулевые значения. `.domain` и `.range` доступны для проверки.

Сравниваемые группы используют один экземпляр шкалы либо одинаковые границы. Изменение масштаба и изменение данных — разные операции.

## 3. Гистограмма из тех же наблюдений

```js
const chart = K.histogram(stage, {
  values: [1, 2, 2, 3, 4],
  bins: [0, 2, 4, 6], // границы, не центры
  x: 210, y: 340, width: 880, height: 205,
  color: C.gold,
  initialPositions: [
    {x:300,y:250}, {x:400,y:280}, {x:450,y:250},
    {x:550,y:280}, {x:650,y:250}
  ]
});
chart.setProgress(1);     // кружки занимают места внутри bins
chart.setBarsProgress(1); // силуэты столбиков растут от нуля
```

`K.histogram(parent, options)` создаёт узлы один раз. `x,y` — верхний левый угол области количественного графика, `width,height` — её размеры. `initialPositions` можно опустить: будет создан исходный ряд над графиком. Начальные позиции не обязаны принадлежать количественной области; автор отвечает за их размещение внутри viewport.

Возвращает:

- `g` — группа; `points` — массив исходных кружков; `bars` — массив прямоугольников.
- `counts` — частоты; `assignments` — `{index,value,bin,level}` для каждого наблюдения.
- `xScale`, `yScale` — фактические шкалы. Вертикальная шкала от 0 до максимальной частоты.
- `setProgress(t)` — сначала разделяет вертикальные позиции, затем сводит горизонтальные позиции к центрам bins; `setBarsProgress(t)` независимо раскрывает высоты.

`values` должны быть непустым массивом конечных чисел. Границы `bins` строго возрастают, все интервалы имеют одинаковую ширину (допуск на арифметику floating point — 1e−9 от ширины). Все интервалы полуоткрыты слева включительно/справа исключительно; последний включает правый край. Наблюдение вне крайних границ или неодинаковая ширина интервалов вызывает `RangeError`. Компонент не удаляет значения, не пересчитывает их и не заменяет их случайной выборкой. Частоты суммируются в исходное число наблюдений. Копии измерений из других визуальных слоёв нельзя передавать как новые наблюдения.

Поддерживается только **гистограмма частот с равными bins**. Неравные ширины намеренно отклоняются: они потребовали бы отдельного режима плотности с другим смыслом высоты и площади. Плотность, веса, интервалы неопределённости и подбор bins этот компонент не вычисляет.

В `02-distribution.js` редактируются `VALUES` и `BINS`. Сначала кружки занимают места по значению, затем собираются в bins, затем за ними вырастают столбики. У произвольной новой раскладки проверьте промежуточные кадры: геометрический helper не может гарантировать отсутствие пересечений при любых стартовых позициях и размере кружков.

## 4. Повторные измерения и средние

```js
const chart = K.replicates(stage, {
  groups: [
    {label:'A', values:[4,5,6], color:C.white},
    {label:'B', values:[1,5,9], color:C.white}
  ],
  domain: [0,10], x:260, y:236, width:760, height:280
});
chart.setProgress(1); // отрезки средних вырастают на правильных высотах
```

Возвращает `g`, `points` (плоский массив SVG-кружков по порядку групп), `means` (SVG-отрезки), `meanValues`, `xScale` и `yScale`. Центр группы `i` находится в `xScale(i + 0.5)`. Каждый кружок имеет `data-group`, `data-replicate`, `data-value`; средний отрезок — `data-group`, `data-mean`.

`setProgress(t)` меняет только ширину отрезков средних. Их высота всегда соответствует точному арифметическому среднему. Все точки остаются на своих индивидуальных значениях. Пустые группы, нечисловые значения и выход за domain вызывают ошибку. Малое горизонтальное разнесение точек внутри группы не кодирует ещё одну переменную.

В `03-replicates.js` дополнительно показан **наблюдаемый диапазон min…max**, явно отделённый от доверительного интервала. Helper не вычисляет p-value, доверительный интервал, SD или SEM и не определяет, независимы ли повторы. Это должен определить автор научного урока. Константы для редактирования — `GROUPS`, `DOMAIN`; оси, подписи и заметки обновляются вместе с ними.

## 5. Точная область исходного изображения

```js
const source = K.sourceWindow(stage, {
  file: 'figure.svg', sourceWidth: 1024, sourceHeight: 640,
  x: 660, y: 175, width: 480, height: 420,
  box: {x:10, y:85, width:490, height:490}
});
source.setBox({x:0,y:0,width:1024,height:640});
source.setFrame({x:280,y:175,width:672,height:420});
```

Возвращает `g`, внутренний `svg`, неизменяемое по данным `image`, а также `.box`, `.frame`, `.fittedFrame`. Запрошенный `box` сохраняется **точно** и должен находиться в границах исходного изображения. Внутреннее окно вписывается по центру доступной `frame`, сохраняя отношение сторон выбранной области. Пустые поля вокруг допустимы; растяжение или добавление соседних пикселей источника для заполнения рамки не выполняется.

Для анимации каждый кадр задаёт `setFrame(frame)` и `setBox(box)`. Область viewport и её `viewBox` имеют одинаковые пропорции. Картинка не обрабатывается и не объявляется заново проанализированными данными. Для перехода между несовместимыми панелями сначала уберите старую за clip, затем смените box, затем введите новую. Для zoom одной и той же панели допустим непрерывный переход области просмотра.

`04-source.js` демонстрирует полный рисунок → одна панель → буквальное наблюдение → граница интерпретации. Файл `assets/illustrative-figure.svg` принадлежит этому набору и содержит только синтетические значения. Используйте его как графический образец, а не как результат научного исследования.

## 6. Источники и переносимость

`D.assets.url(file)` возвращает путь к asset либо встроенный URL из standalone-сборки. `F.image` и `K.sourceWindow` используют этот resolver. Не вставляйте абсолютные пути личного компьютера в сцены и не ссылайтесь из standalone HTML на внутренние исследовательские заметки, которых рядом с файлом не будет.

Глобальный `LESSON.source` задаёт источник урока. Аргумент `source` в `F.stage` сохраняется как метаданные и показывается в раскрываемом разделе в конце пояснений, хотя footer скрыт на холсте. В `T.evidence` поля `url` и `sourceLabel` могут его переопределить; пустой `url` означает отсутствие внешней ссылки. Собственная иллюстрация должна оставаться обозначенной собственной иллюстрацией, даже если у урока есть основная статья.

В языковых пакетах используйте точные исходные строки и целиком ограниченные шаблоны для динамических подписей. Перевод не меняет числовые SVG-атрибуты, input.value, URL и `data-*`; `code`, `pre` и редактируемый текст исключены. Язык внутри оригинального изображения также сохраняется: переводятся окружающие подписи и пояснения, а не научный рисунок. Подробный контракт находится в [languages.md](languages.md).

Данные, наблюдение и интерпретация получают разные формулировки. Числовой helper гарантирует геометрию своих входов, но не научную достоверность самих входов или причинного объяснения.

## 11. Постоянная оболочка и последовательное рисование

Компактная оболочка, добавленная в 0.6.0, объединяет пояснения, QA и поиск в одном пространстве чтения и оставляет пять постоянных нижних контролов. `shell.css` загружается последним; детали в [shell.md](shell.md). Новые `F.phase`, `F.revealStroke` и `F.growArrow` подробно описаны в [interaction.md](interaction.md). Координаты `T.text`/`F.label` используют вертикальную середину строки. Проверка размещения должна сравнивать её фактическую рамку с целевой ячейкой/областью, включая промежуточные кадры, а не только со всем холстом.
