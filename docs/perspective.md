# Ракурс и раскрытие третьей координаты

`K.project3D` и `K.spatialScene` показывают явно заданные трёхмерные координаты средствами SVG. Два готовых примера решают разные задачи: **смена ракурса сохраняет данные**, а **подъём над плоскостью раскрывает известное третье значение**. Выберите нужный пример и замените его небольшие учебные данные; создавать отдельный 3D-движок не требуется.

Подключите `js/perspective.js` после `js/film.js` и `js/patterns.js`, перед использующими его эпизодами. Примеры галереи — `js/episodes/12-viewpoint.js` и `js/episodes/13-dimension.js`. Для каждой сцены предусмотрены начальный кадр и три шага, четыре состояния заметок, две проверочные задачи и авторский RU/EN. Переключение языка меняет текст, сохраняя ракурс и текущий шаг.

## Что именно проектируется

`K.project3D(xyz, camera)` принимает координаты `[x,y,z]` и камеру `{cx,cy,scale,yaw,pitch}`, возвращает `{x,y,depth}`. Значения камеры по умолчанию: `cx=0,cy=0,scale=1,yaw=0,pitch=0`. Углы задаются **в градусах**; `scale` — число единиц SVG на единицу координат. Сначала применяется поворот `yaw` вокруг z, затем `pitch` вокруг x:

```text
u     = cos(yaw)·x − sin(yaw)·y
v     = sin(yaw)·x + cos(yaw)·y
up    = cos(pitch)·v − sin(pitch)·z
depth = sin(pitch)·v + cos(pitch)·z
screenX = cx + scale·u
screenY = cy − scale·up
```

В формулах углы переводятся в радианы. При `yaw=0,pitch=0` видна плоскость xy, а z не влияет на экранное положение. При отрицательном `pitch` увеличение z поднимает точку на экране. Это явная договорённость о знаках, а не автоматический выбор направления «вверх» для любого ракурса.

Здесь **ортографическая проекция**, без перспективного деления: удалённые точки не уменьшаются, параллельные линии остаются параллельными. `depth` нужен для порядка отрисовки точек. Геометрические расстояния рассчитывайте по исходным `xyz`, а не по пикселям: проекция может совместить разные точки и укоротить отрезок вплоть до нуля.

## Небольшая пространственная сцена

```js
const space = K.spatialScene(K.viewport(v.svg), {
  camera: {cx: 450, cy: 410, scale: 90, yaw: 0, pitch: 0},
  points: [
    {id: 'sample', xyz: [1, 1, 0], color: C.blue, r: 7, opacity: 1}
  ],
  segments: [
    {id: 'vector', from: [0, 0, 0], to: [1, 1, 0],
     color: C.blue, width: 3, arrow: true, opacity: 1},
    {id: 'height', from: [1, 1, 0], to: [1, 1, 0],
     color: C.gold, width: 1.5, dash: '5 4', opacity: 0}
  ],
  polygons: [
    {id: 'floor', vertices: [[-2,-1,0], [2,-1,0], [2,2,0], [-2,2,0]],
     color: C.blue, opacity: 0.08}
  ],
  labels: [
    {id: 'sample-label', xyz: [1,1,0], text: 'Наблюдение',
     color: C.blue, size: 20, dx: 12, dy: -12, anchor: 'start', opacity: 1}
  ]
});
```

ID должны быть уникальны **между всеми четырьмя видами объектов**. Координаты, вершины и камера копируются; последующее изменение переданного массива не меняет сцену. Поля `from`, `to`, `vertices` и `labels.xyz` задают координаты непосредственно: это не ссылки на ID точек. Если точка и конец стрелки обозначают одно наблюдение, обновляйте оба из одного состояния. `setPoint` не перемещает надпись с похожим ID; геометрия многоугольников и привязки надписей задаются при создании.

Стили по умолчанию: белый цвет, `opacity=1`, радиус точки `r=6`, ширина отрезка `width=2`, `dash=''`, `arrow=false`; для надписи `size=22,dx=0,dy=0,anchor='middle'`. Смещения надписи измеряются в экранных единицах после проекции её `xyz`.

| Метод | Действие |
|---|---|
| `setCamera(patch)` | Меняет заданные поля камеры, сохраняет остальные. |
| `setPoint(id, xyz)` | Меняет координаты существующей точки. |
| `setSegment(id, from, to)` | Меняет оба конца существующего отрезка/стрелки. |
| `setOpacity(id, opacity)` | Меняет видимость существующего объекта без его удаления. |
| `render()` | Пересчитывает экранные положения из текущих данных и камеры. |
| `snapshot()` | Возвращает отдельные изменяемые копии `{camera,points,segments,polygons,labels}` с мировыми координатами и нормализованными стилями. Изменение снимка не меняет сцену. |

Все setter-методы сразу отрисовывают результат и возвращают компонент для цепочки вызовов. Набор узлов создаётся один раз. Геометрия надписей следует за проекцией, но текст, радиусы точек, толщина линий и наконечники остаются в экранных единицах и не наклоняются вместе с плоскостью. Камера не подбирает масштаб автоматически и не устраняет пересечения подписей. Проверяйте всю траекторию внутри области `x=60…1220,y=147…610`, включая отступы текста и наконечники.

Компонент проверяет конечность чисел, форму координат, ID и параметры объектов. Не передавайте числовые строки, разреженные массивы или отсутствующие координаты; многоугольнику нужны хотя бы три вершины. Пустая сцена разрешена. Неизвестные поля камеры отклоняются. Прозрачность должна находиться в `[0,1]`, масштаб и размеры — быть положительными. До изменения состояния и DOM проверяется предполагаемая проекция, в том числе численное переполнение. Допустимая конечная проекция всё равно может оказаться вне отведённого окна: компонент не подбирает компоновку за автора.

## Анимация и ручное управление

Держите камеру, раскрываемую координату и подпись в одном `paint`. Для ползунка используйте `F.driver`, чтобы новый ввод отменял предыдущий переход:

```js
const state = {yaw: 0, pitch: 0};
function paint() {
  space.setCamera({yaw: state.yaw, pitch: state.pitch});
  // Здесь же синхронизируйте ползунок и реплику на холсте.
}
const driver = F.driver(state, paint);
ctx.onDispose(driver.dispose);
paint();
ctx.step(() => driver.to({yaw: -25, pitch: -50}, {duration: 2000}));
// В обработчике ползунка: driver.set({yaw: value});
```

Сначала завершите поворот, дайте зрителю рассмотреть результат, затем раскрывайте новую ось или отношение. Для подъёма точки используйте отдельный числовой прогресс: `[x,y,t*z]`, конец вектора и вертикальный отрезок обновляются вместе. Сохраняйте тень `[x,y,0]`; подпись должна явно говорить о раскрытии координаты. Не называйте такое промежуточное положение измерением во времени. Жизненный цикл и отмена подробнее описаны в [interaction.md](interaction.md).

## Два образца и границы вывода

**12 — смена ракурса.** Одно фиксированное синтетическое облако: фронтальное наложение → косой вид → вид сбоку → возврат. Цвет и ID каждого наблюдения сохраняются; ракурс меняет перекрытия, но не исходные координаты и расстояния. Новое разделение на экране само по себе не доказывает существование биологических классов.

**13 — третья координата.** Знакомая плоскость xy → её наклон → ось z → подъём вектора с сохранённой тенью. Третье значение задано заранее; изменение картинки объясняет представление этого значения. Это не восстановление скрытого признака из двумерной картинки.

Обычный 2D UMAP или рисунок статьи нельзя «выдавить» в 3D и получить отсутствующие измерения. Если автор предоставляет настоящее трёхмерное представление, можно поворачивать именно его; исходное пространство признаков этим не восстанавливается. Пример облака — схема проекции, не алгоритм UMAP. Оригинальные изображения остаются отдельными источниками без выдуманной глубины.

Порядок слоёв фиксирован: многоугольники → отрезки → точки → надписи. Сортировка переставляет только существующие кружки внутри их слоя, сохраняя узлы и ID: меньшая глубина рисуется раньше, положительная глубина направлена к зрителю; при равной глубине сохраняется исходный порядок. Полноценной видимости поверхностей нет: отрезки, многоугольники и текст не получают общего z-buffer, скрытые части линий не отсекаются. Для плотной молекулярной поверхности или взаимного перекрытия сеток нужен другой инструмент; этот компонент предназначен для небольших читаемых учебных схем.

## Происхождение и интерпретация

Операции смены ракурса фиксированного облака и раскрытия высоты над плоскостью адаптированы из локальных курсовых реализаций. Текущий helper использует собственную явную ортографическую камеру, постоянные узлы, экранные подписи и проверки входа. История кода и границы прав — в [provenance.md](provenance.md); обе реализации доступны в самой галерее.

Для каждого поворота сформулируйте, какое отношение он открывает. После поворота остановите камеру, оставьте читаемые подписи и только затем вводите следующую операцию. Сведения об отличиях от UMAP: [официальные параметры, включая n_components](https://umap-learn.readthedocs.io/en/latest/parameters.html) и [ограничения кластерной интерпретации](https://umap-learn.readthedocs.io/en/latest/clustering.html). Эти источники описывают метод; синтетическое облако галереи не является его реализацией.

В примере 13 камера и раскрытие координаты используют отдельные контроллеры F.driver. Ручная смена ракурса останавливает текущий поворот, но не обрывает наполовину рост оси или раскрытие z. Оба контроллера освобождаются через ctx.onDispose.
