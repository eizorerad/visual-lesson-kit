# Порог, precision/recall и average precision

`starter/js/threshold.js` добавляет два независимых от научной темы API. Загружайте его после `lesson.js`, `film.js` и `patterns.js`, перед эпизодами. Нужны существующие `D.dom`, `F`, `C` и `K.linearScale`; новых зависимостей нет. Данные, источники и подписи предоставляет автор.

## Расчёт ранжирования

```js
const ranking = K.binaryRanking({
  observations: [
    {id: 'a', score: 0.9, positive: true},
    {id: 'b', score: 0.6, positive: false},
    {id: 'c', score: 0.6, positive: true}
  ]
});
ranking.at(0.6);
// {threshold:0.6, selected:3, TP:2, FP:1, TN:0, FN:0,
//  precision:2/3, recall:1}
ranking.averagePrecision; // 5/6
```

`observations` — непустой плотный массив. `id` — непустая уникальная строка, `score` — конечное число, `positive` — boolean. Неизвестные поля отклоняются. Компонент копирует и замораживает данные; исходный массив не сортируется и не изменяется. Копии в `.observations` дополнительно содержат исходный `index`.

Правило всегда одно: **score ≥ threshold**. Одинаковые score входят целой группой; порядок записей внутри группы не влияет на метрики. `at(threshold)` принимает конечное число и возвращает целочисленные счётчики. При отсутствии выбранных случаев `precision === null`. При отсутствии положительных случаев `recall === null` и `averagePrecision === null`. Нулевая метрика и неопределённая метрика — разные состояния.

Результат также содержит:

- `positives`, `negatives` — общие числа классов;
- `groups` — группы по убыванию score: `score`, `ids` и накопленные счётчики/метрики;
- `curve` — точки `{score, recall, precision}` после каждой группы;
- `rectangles` — ненулевые по ширине участки `{left, right, precision, score}`;
- `averagePrecision` — сумма `(right − left) × precision`.

Ширина прямоугольника — прирост recall, высота — precision **после** включения группы. Это дискретная average precision (AP), без интерполяции огибающей. Она отличается от трапецеидальной площади по PR-точкам. Название «AUPRC» само по себе не задаёт правило интегрирования; при объяснении чужой статьи проверьте метод. AP не является precision одного выбранного порога.

## Связанная геометрия

```js
const chart = K.thresholdCurve(stage, {
  ranking,
  scoreDomain: [0, 1],
  scoreFrame: {x:190, y:275, width:460, height:140},
  prFrame: {x:840, y:275, width:300, height:240},
  threshold: 0.95,
  radius: 8
});
chart.setThreshold(0.6);
chart.showPR(1);       // opacity 0…1
chart.revealArea(1);   // opacity 0…1; площадь всего ранжирования
chart.stats();
```

Обе frame обязательны и задают верхний левый угол количественного графика. `scoreDomain` — два конечных возрастающих значения, охватывающих все score. Шкалы PR всегда равны `[0,1]`. `threshold` по умолчанию равен верхней границе scoreDomain; `radius` по умолчанию равен 8. Порог renderer должен оставаться внутри заданного domain. Чтобы показать пустой выбор, верхнюю границу следует поставить выше максимального score: при равенстве максимальный случай уже включён. Числа score не обязаны быть вероятностями.

Свойства результата: `g`, `scoreGroup`, `prGroup`, `points` (постоянные SVG-группы случаев), `curve` (постоянный path), `areaRects`, `dot`, `thresholdLine`, `scoreScale`, `recallScale`, `precisionScale`, `scoreDomain`, `scoreFrame`, `prFrame`. Группы случаев имеют `data-observation-id`, `data-score`, `data-positive`, `data-selected`; автор может добавить в них собственные подписи. Их координаты и идентичность не меняются при выборе порога.

Пока площадь скрыта, белый путь показывает пройденную часть ранжирования. При `revealArea(t > 0)` белый путь показывает **полное ранжирование**, потому что прямоугольники всегда относятся к полной AP. Золотая точка продолжает обозначать текущий порог. `revealArea(0)` возвращает режим пройденной части. Высоты и ширины прямоугольников не растягиваются для эффекта появления: меняется только прозрачность. Без положительных случаев PR-путь и площадь пусты, точка скрыта.

Случаи разделены по известному классу на две строки. Совпадающие score внутри класса располагаются вертикально; слишком высокий стек и пересечение любых маркеров отклоняются до добавления DOM. Между центрами требуется не менее двух радиусов плюс 4 единицы на контур и зазор. Близкие, но различные score не раздвигаются, потому что это исказило бы шкалу. Автор должен проверить плотность точек и своих подписей, выбрать достаточную ширину, меньший радиус или другой вид графика. Компонент добавляет числовые деления до 27 единиц ниже frame и до 17 единиц слева от PR-frame: оставляйте место под них. Он не выбирает оптимальный порог, не калибрует вероятности и не оценивает неопределённость.

## Пример и управление

`starter/js/episodes/11-threshold.js` содержит начальное состояние и три шага: две выбранные записи → совместное включение равных score → полный обход и AP. Шесть случаев придуманы и подписаны как учебные. AP равна 0,70. Четыре заметки объясняют каждое состояние, две записи `qa` разбирают типичные ошибки.

Эпизод использует `F.driver(state, paint)` и `ctx.onDispose(driver.dispose)`. Ручной ползунок отменяет прежние записи состояния, обновляет подпись и скрывает итоговую площадь. Перед раскрытием AP последний шаг сначала завершает обход всех score. Анимируемый порог непрерывен; счётчики всегда целые. Знак `≈` у промежуточного порога предупреждает об округлении экранной подписи до двух знаков.

## Происхождение и проверка

Связь порога, выбранных наблюдений и ступенчатой площади адаптирована из локальных курсовых реализаций. Галерея использует шесть явно заданных синтетических случаев; она не содержит результатов статьи. История кода и границы прав — в [provenance.md](provenance.md).

`node --test tests/threshold.cjs` проверяет известную AP, равные score, неопределённые метрики, защиту данных/DOM, площадь SVG в числовых координатах, фиксированные узлы, промежуточные состояния, повтор шагов и прерывание анимации ползунком. Это проверки jsdom и геометрии, не проверка живого браузера.
