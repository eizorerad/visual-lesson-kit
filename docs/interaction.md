# Управление состоянием во время анимации

`F.tween` подходит для последовательных сцен без одновременного ручного управления. Для сцены с ползунком используйте локальный контроллер:

```js
const state = { value: 0, detail: 0 };
const driver = F.driver(state, paint);
ctx.onDispose(driver.dispose);
// callback ползунка:
driver.set({ value: newValue });
// зарегистрированный шаг:
ctx.step(() => driver.to({ value: 1 }, { duration: 1600 }));
```

`paint` читает текущее состояние и согласованно обновляет рисунок, числа, ползунок и подпись. `driver` сам не вызывает начальный `paint`: вызовите его после создания объектов и контролов.

- `set(patch)` мгновенно применяет значения и инвалидирует предыдущую анимацию этого контроллера.
- `to(patch, {duration=1700, after?})` начинает переход от текущих значений. Возвращает Promise с `{completed:true}` при завершении и `{completed:false}` при замене или отмене. `duration:0` сохраняет точный конечный кадр. Параметры копируются при старте.
- `cancel()` сохраняет текущие значения и завершает ожидание как отменённое. Контроллер можно использовать дальше.
- `dispose()` отменяет ожидание и запрещает дальнейшие `set`/`to`. Повторный вызов безопасен.

Состояние и patch содержат конечные числа; patch может менять только уже объявленные поля. Проверки происходят до отмены текущего перехода. Не изменяйте `state` напрямую при активном переходе. Для дискретных счётчиков интерполируйте порог или прогресс, а целые количества вычисляйте из текущего набора наблюдений.

`after` запускается только при действительном завершении, если новая операция ещё не заменила старую. Не используйте безусловное `.then(...)` для отложенных изменений сцены: Promise отменённого перехода тоже завершается. Для внешней цепочки проверяйте `result.completed` и жизнь сцены.

Если `paint` бросает исключение во время перехода, Promise отклоняется, последующие кадры этого перехода инвалидируются, `after` не запускается. Состояние остаётся на кадре, в котором произошла ошибка; автоматического отката DOM нет. Ошибка синхронного `set` также передаётся вызывающему коду.

Старый tween остаётся в общей очереди `A` до её обычного завершения, но его кадры больше ничего не записывают. Контроллер не вызывает `A.finishAll` и не завершает анимации других объектов. Режим мгновенного воспроизведения, скорость и reduced motion по-прежнему обрабатывает `A`.

## Уход со сцены

`ctx.onDispose(fn)` регистрирует освобождение ресурсов при перестроении/смене сцены и при ошибке её создания. Проигрыватель вызывает его до глобального завершения оставшихся анимаций. Зарегистрируйте здесь `driver.dispose`, снятие внешних обработчиков и очистку собственных таймеров. Эта функция не освобождает произвольные ресурсы автоматически.

При быстром переходе проигрыватель также пропускает ещё не начавшиеся шаги старой сцены и не позволяет старому мгновенному воспроизведению заменить новую сцену.

## Происхождение

Локальный контроллер состояния развивает приёмы отмены устаревших кадров из курсовых реализаций. В библиотеке он включает проверку входа, отмену ожидания и позднего завершения, `dispose` и жизненный цикл сцены. История кода не является новым лицензионным заявлением; см. [provenance.md](provenance.md).

## Последовательные фазы и раскрытие линий (0.6.0)

Эти три помощника преобразуют переданный прогресс и существующие SVG-узлы. Они не создают scheduler, не назначают шаги и не меняют научные данные. Используйте их внутри того же `paint()`, который обновляет числа и подпись.

```js
const state = { explain: 0 };
const link = F.path(v.svg, [[260, 340], [490, 290], [700, 340]], C.blue, 3);
const flow = F.arrow(v.svg, C.gold, 3);
const result = F.label(v.svg, 970, 340, 'Результат', 28, C.white);
function paint() {
  const p = state.explain;
  F.revealStroke(link, F.phase(p, 0, 0.45));
  F.growArrow(flow, 720, 340, 850, 340, F.phase(p, 0.45, 0.8));
  F.opacity(result, F.phase(p, 0.8, 1));
}
paint();
F.step(ctx, v, state, { explain: 1 }, paint,
  'Сначала устанавливаем связь, затем читаем её результат.', 2200);
```

Здесь сначала рисуется связь, затем появляется направленная стрелка и только после неё — результат. Если ручной ввод может менять `explain`, используйте `F.driver` вместо независимого `F.step`/`F.tween`, чтобы отменять предыдущие кадры локально. Сохраняйте те же узлы при любом положении ползунка и обратном воспроизведении.

- `F.phase(t, start=0, end=1)` возвращает 0 до начала интервала и 1 после конца. Внутри используется `q*q*(3-2*q)`, где `q=(t-start)/(end-start)`. Все три аргумента должны быть конечными числами, `end > start`; иначе выбрасывается `RangeError`. Это сглаженный прогресс операции, а не новое значение измерения.
- `F.revealStroke(node,t)` ограничивает конечный `t` до 0…1 и раскрывает штрих существующего SVG-пути/линии через нормализованные `pathLength`, `stroke-dasharray`, `stroke-dashoffset`. При первом обращении запоминает эти три исходных атрибута; при t=1 восстанавливает их, включая исходный пунктир. При t=0 узел скрыт, при t>0 его opacity становится 1. Геометрия `d`/координат и идентичность узла не меняются. Во время частичного раскрытия помощник владеет перечисленными dash-атрибутами; не меняйте их параллельно другим компонентом. Если нужен независимый fade, применяйте opacity к родительской группе. Неподходящий узел или неконечный прогресс вызывает `TypeError`.
- `F.growArrow(arrow,x1,y1,x2,y2,t)` принимает существующий результат `F.arrow`. Начало `(x1,y1)` остаётся постоянным; конец движется к `(x2,y2)` по ограниченному до 0…1 прогрессу, а наконечник следует за ним. При t=0 группа скрыта, при t>0 opacity равна 1. Координаты и прогресс должны быть конечными, иначе `TypeError`. Возвращается та же стрелка; узлы shaft/head не заменяются.

Не заставляйте весь рисунок одновременно влетать в кадр: движение должно показывать причинный или вычислительный порядок. Отведите отдельные интервалы для очистки старого слоя, перемещения объекта и появления его новой подписи. Сверяйте реальную рамку каждого текста с предназначенным ему блоком на нескольких промежуточных кадрах: конечные координаты и отсутствие `NaN` не подтверждают отсутствие наложений. `T.text` и `F.label` используют `dominant-baseline="middle"`; y относится к середине строки.

### Один расчёт видимости для входа и выхода

Если группа сначала появляется, затем исчезает, вычисляйте её opacity одной записью. Два последовательных вызова «показать» и «скрыть» перезапишут друг друга: будущий слой может оказаться видимым уже в первом кадре.

```js
// p — общий прогресс сцены. Группа появляется на 1…2 и уходит на 3…4.
const entering = F.phase(p, 1, 2);
const leaving = F.phase(p, 3, 4);
F.opacity(group, entering * (1 - leaving));
```

До p=1 группа скрыта, между p=2 и p=3 полностью видна, после p=4 снова скрыта. Подписи и оси будущего шага должны находиться внутри той же группы. Проверяйте именно начальный кадр и обе границы раскрытия; проверка конечных координат этот дефект не обнаружит.

## Вход в следующую сцену

Проигрыватель 0.6.0 добавляет при переходе через границу сцены короткое появление нового frame за 240 ms через opacity. Старая сцена уже освобождена; геометрия не движется. Это только оболочка навигации, она не заменяет пошаговую анимацию научной операции. Прямой `D.deck.show` и hash остаются мгновенными, reduced motion отключает эффект. Подробности и проверки быстрого перехода — [shell.md](shell.md).
