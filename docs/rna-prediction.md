# Предсказание структуры РНК: от данных к форме

Переиспользуемый шаблон из **20 сцен и 91 состояния**, перенесённый из одобренной презентации. Он сохраняет её рисунки, порядок акцентов, длительности, плавное ускорение/замедление, номера нуклеотидов, обе локали и вопросы с источниками.

## Создать урок в этом стиле

```sh
python3 create.py ../my-rna-prediction --template rna-prediction \
  --title "Как предсказать структуру РНК" \
  --background black --palette ocean --font sans
python3 ../my-rna-prediction/build/bundle.py
```

Откройте `../my-rna-prediction/dist/lesson.html`. Файл автономный: библиотеки, данные и шрифты встроены. Готовая библиотечная сборка — `examples/rna-prediction.html`; команда обновления — `python3 tools/build-rna-prediction.py`. Её `--check` сравнивает сохранённый пример с новой сборкой. Проектный `build/bundle.py --check` только проверяет возможность сборки, поэтому после изменений сначала запускайте сборку без этого флага.

Для другой темы используйте [приёмы постановки и временные кривые](cinematic-explanation.md). Для собственной цепи используйте [отдельный компонент PM](rna-pair-molecule.md). Существующие шаблоны и глобальная скорость не меняются. Цвет `ocean` выбран явно в команде; другие палитры остаются доступны.

## Что добавлено в библиотеку

| Переиспользуемый материал | Путь в созданном проекте |
| --- | --- |
| Один актор: последовательность → дуги → шпилька → объём | `js/rna-pair-molecule.js`, API `PM.create` |
| Энергия конкретного мотива → член формулы → сумма | `js/recipes/rna-prediction/prediction-thermo-story.js` |
| Альтернативные пары → реальные оценки → выбор MFE → 2D | тот же файл, сцена `story-thermo-search` |
| Колонки MSA → наблюдения → соответствующие дуги → 2D | `js/recipes/rna-prediction/prediction-alignment-story.js` |
| Ансамбль → вклад каждой структуры → вероятность одной пары | `js/recipes/rna-prediction/prediction-ensemble-story.js` |
| Все 99 структур короткой цепи, энергии мотивов и вероятности | `assets/rna-prediction/thermo-example.json` |
| Воспроизведение и встраивание данных | `build/rna-prediction-data.py` |
| Браузерные и численные проверки | `qa/rna-prediction/` |

Рецепты — редактируемые композиции, не универсальные вычислители для произвольного входа. Их можно брать по одному: загрузить обычный runtime, `rna-common.js`, нужные данные/PM и выбранный файл рецепта, затем `rna-order.js`. Окончательный порядок выбранных определений задаёт `RNA.finish()` в `rna-common.js`. Не загружайте одновременно две версии `rna-common.js` из разных шаблонов. В исходном HTML видно точное расположение зависимостей.

Компонент PM работает отдельно от рецептов и требует только обычные SVG, живую палитру `C` и текстовые контракты `L`. Он поддерживает один непрерывный вложенный стебель, одну шпилечную петлю и внешние хвосты. Он не рисует произвольные многостебельные топологии или псевдоузлы автоматически. Координаты атомов в дополнительных сценах остаются задачей существующего `molecular-coordinates`.

## Сценарий

| Сцена | Состояния | Видимая операция |
| --- | ---: | --- |
| `story-thermo-score` | 7 | Та же цепь становится кандидатом; подсвеченные мотивы передают свои энергии в формулу. |
| `story-thermo-search` | 7 | Копии последовательности обозначают гипотезы; реальные оценки выбирают минимум; дуги превращаются в шпильку. |
| `story-thermo-shape` | 5 | Пары сохраняются при добавлении глубины и повороте; меняется только непарная петля. |
| `story-ensemble` | 6 | Веса структур собираются у одной пары, затем появляются остальные парные вероятности. |
| `pred-beam` | 4 | Приближённый лучевой поиск для длинных цепей. |
| `story-alignment` | 8 | Строки сопоставляются; наблюдения из колонок достигают своих дуг; те же буквы образуют 2D. |
| `story-alignment-shape` | 5 | Карта пар сохраняется в разных схематических пространственных формах. |
| `pred-phylogeny`, `pred-hybrid` | 4 + 4 | Зависимость строк и сочетание источников свидетельств. |
| `rna-pseudoknot`, `rna-cotranscription`, `rna-ions`, `pred-tools` | 4 + 4 + 5 + 4 | Ограничения топологии, история синтеза, среда и выбор инструмента. |
| `rna-trna-real`, `rna-nucleotide`, `rna-chemistry`, `rna-pairs`, `rna-loops`, `pred-dp`, `rna-geometry` | 4 + 3 + 3 + 4 + 3 + 4 + 3 | Дополнительные атомные планы, мотивы, алгоритм и геометрические ограничения. |

## Научные границы

Вычисления сделаны для авторской последовательности **GGACGAAACGUCC**: ViennaRNA 2.7.2, Turner 2004, 37°C, моновалентная соль 1.021 M, `dangles=2`. Это реальные значения модели, а не назначенные вручную энергии. MFE `(((((...)))))` имеет ΔG = −4.90 ккал/моль и вероятность 85.37% в полном 99-структурном ансамбле. Вероятность пары 5–9 — 87.46%. Численная проверка не является экспериментальной валидацией молекулы.

Шесть строк MSA придуманы для объяснения. Цветные наблюдения не являются независимыми голосами, p-value или выполненным расчётом RNAalifold/R-scape. 3D-схема добавляет геометрические допущения к парным ограничениям; она не является выходом RNAfold, атомными координатами или физической траекторией. Дополнительные атомные сцены используют отдельно обозначенные депонированные структуры.

Список литературы и точные условия: `assets/rna-prediction/SOURCES.md`, `assets/rna-prediction/COMPUTATION.md`. Источники также доступны в заметках и вопросах каждой сцены.

Результаты проверки переноса в библиотеку: `assets/rna-prediction/VERIFICATION.md`.

## Проверить свой экземпляр

Из папки созданного проекта:

```sh
node qa/rna-prediction/science.cjs
python3 qa/rna-folding/science.py
python3 build/bundle.py
node qa/rna-prediction/layout.cjs --full
node qa/rna-prediction/motion.cjs
node qa/rna-prediction/interaction.cjs
```

Численный Node-аудит работает без ViennaRNA. Для изменения/повторного расчёта модели нужна отдельная среда с `ViennaRNA==2.7.2`; инструкция находится в `COMPUTATION.md`. После изменения статического JSON используйте `python3 build/rna-prediction-data.py --embed-only`, затем пересоберите HTML. Это встраивает данные, но само не пересчитывает энергии.

Браузерные проверки требуют Playwright и Chromium/Chrome; можно передать путь к установленному Playwright через `PLAYWRIGHT_MODULE`. Они проверяют все состояния, промежуточные кадры и управление. Проверка мышью/эмуляцией не заменяет испытания жестов на физическом сенсорном устройстве.
