# Матрицы и разделение наблюдений

Два независимых компонента дополняют `K`: `matrices.js` и `partitions.js`. Их загружают после `film.js`, `patterns.js` и общих библиотек. Они используют `F`, `P`, `C` и `D.dom`; дополнительный CSS не нужен. Компоненты получают готовые данные и явные назначения. Они не выполняют кластеризацию, выборку, обучение или статистический тест.

## K.heatmap

```js
const matrix = K.heatmap(parent, {
  values: [[-2, 0, 2], [1, -1, .5]],
  rowLabels: ['R1', 'R2'],
  columnLabels: ['C1', 'C2', 'C3'],
  domain: [-2, 2],
  center: 0,
  colors: [C.blue, '#20242b', C.red],
  x: 300, y: 300,
  cellWidth: 64, cellHeight: 46,
  gap: 10, labelSize: 24
});
```

Обязательны непустая прямоугольная числовая `values`, явный возрастающий `domain` из двух конечных чисел, `x`, `y`, `cellWidth`, `cellHeight`. Размеры ячеек положительны. `gap` по умолчанию 6 и неотрицателен, `labelSize` по умолчанию 22 и положителен. Пропуски в массивах и неконечные значения отклоняются. Значения за пределами `domain` вызывают исключение, не обрезаются и не исчезают. Подписи по умолчанию R1… и C1…; переданный массив должен содержать подпись для каждой позиции.

Цветовая шкала состоит из трёх шестизначных hex-цветов. `center` по умолчанию равен середине диапазона и должен лежать строго внутри него. Интерполяция RGB выполняется отдельно на отрезках `[min, center]` и `[center, max]`. Это визуальная шкала, не нормировка данных. Одна и та же функция `matrix.colorScale(value)` действует при любой перестановке. Если нужна другая нормировка, автор рассчитывает и объясняет её отдельно.

| Возвращаемое поле или метод | Смысл |
| --- | --- |
| `g`, `rowGroups`, `cells` | Постоянные SVG-объекты; `cells` перечислены по исходным строкам, затем столбцам. |
| `labels.rows`, `labels.columns` | SVG-подписи; подпись строки принадлежит её группе. |
| `values`, `domain`, `colors`, `center` | Скопированные исходные параметры; массивы заморожены. |
| `cell(r, c)` | Ячейка по исходным, нулевым индексам. |
| `position(r, c)` | Текущий верхний левый угол ячейки `{x, y}`, включая отдельный сдвиг строки. |
| `setSelection({row?, column?})` | Выделяет исходную строку, столбец или их пересечение; `{}` снимает выделение. Цветовой `fill` сохраняется, соседние ячейки получают прозрачность 0.3. |
| `setRowOffset(r, dx=0, dy=0)` | Задаёт абсолютный дополнительный сдвиг строки для постановки движения. |
| `setOrder(order, progress=1)` | Интерполирует позиции по явно заданным перестановкам. |

В `setOrder` поле `rows` — список исходных индексов в новом экранном порядке. Аналогично устроено `columns`. Каждая переданная перестановка должна быть полной биекцией: без пропусков, повторов и неизвестных индексов. Неуказанное поле означает исходный порядок. Проверка выполняется до изменения SVG.

```js
matrix.setOrder({
  rows: [1, 0], columns: [2, 0, 1],
  fromRows: [0, 1], fromColumns: [0, 1, 2]
}, progress);
```

`progress` — конечное число, ограничиваемое диапазоном 0…1. Это абсолютная интерполяция от `fromRows` / `fromColumns`, а не очередной шаг от текущего положения. Если `from…` не заданы, начальным является исходный порядок. Для обратного движения явно передают исходную перестановку в `from…`. Значения, исходные индексы и DOM-идентичность ячеек сохраняются. `data-display-row` и `data-display-column` обозначают дробные позиции во время движения; `data-row-index` / `data-column-index` всегда обозначают исходную пару.

Сам компонент не решает задачу разведения траекторий. Прямая одновременная перестановка может пересечь строки. В эпизоде 7 выбранная R3 сначала выходит вправо на 360 единиц через `setRowOffset`, затем меняет высоту, пока остальные строки опускаются, и возвращается к сетке. Числа размещены внутри постоянных групп строк и движутся вместе с ними. Для анимации столбцов автор должен также привязать собственные дополнительные надписи к `position(r,c)`; компонент управляет только своими ячейками и подписями осей.

## K.partitionActors

```js
const observations = K.partitionActors(parent, {
  items: [{id: 'S1'}, {id: 'S2'}, {id: 'S3'}, {id: 'S4'}],
  initialGroup: 'all',
  groups: {
    all: {x: 280, y: 278, columns: 2, dx: 75, dy: 72, color: C.white},
    build: {x: 790, y: 278, columns: 2, dx: 75, dy: 72, color: C.teal},
    reserve: {x: 230, y: 526, columns: 2, dx: 75, dy: 72, color: C.gold}
  },
  radius: 11, labelSize: 18, labelOffset: 29
});
const split = {build: ['S1', 'S2'], reserve: ['S3', 'S4']};
observations.setPartition(split, progress);
```

`items` — непустой массив записей с уникальными непустыми строковыми `id`. Метка `label` по умолчанию совпадает с ID. Каждый элемент получает один постоянный SVG-кружок и подпись. Дополнительные поля записи сохраняются в поверхностной замороженной копии; веса, повторная выборка и агрегация отсутствуют. Пропуски в `items` и массивах назначения отклоняются.

Каждая именованная область задаёт конечные `x`, `y`, положительные `dx`, `dy` и положительное целое `columns`. Цвет по умолчанию белый; переданный цвет должен быть шестизначным hex. `initialGroup` должен существовать. Размер кружка и шрифта положителен. Позиции внутри области заполняются построчно в **исходном порядке `items`**, поэтому перестановка ID внутри списка назначения не перемешивает объекты.

```js
observations.setPartition(
  {all: ['S1', 'S2', 'S3', 'S4']},
  progress,
  {from: split}
);
```

Во входном назначении каждый исходный ID должен встретиться ровно один раз. Неизвестные группы, неизвестные ID, повторы или недостающие наблюдения вызывают исключение до изменения объектов. Группу с нулём наблюдений можно опустить или передать как `[]`. По умолчанию интерполяция начинается с `initialGroup`; для последующего или обратного движения нужен явный `{from: previousPartition}`. Конечный `progress` ограничивается диапазоном 0…1. Позиции и цвета линейно интерполируются; время и easing задаёт внешний `F.step` / `F.tween`.

| Возвращаемое поле или метод | Смысл |
| --- | --- |
| `g` | Общая SVG-группа компонента. |
| `actors` | Записи `{g, dot, label, item}` в исходном порядке наблюдений. |
| `items` | Замороженные копии исходных записей. |
| `position(id)` | Текущий центр кружка `{x, y}`; неизвестный ID отклоняется. |
| `assignments` | Замороженное соответствие ID → целевая группа текущего перехода. |
| `counts` | Замороженные количества в **целевом назначении**, включая нулевые группы. |
| `setPartition(partition, progress, {from})` | Применяет валидированный переход без пересоздания наблюдений. |

`counts` во время движения не означает количество кружков, физически пересёкших нарисованную границу области. Целевое назначение уже известно, а `position(id)` отражает промежуточную геометрию. Компонент гарантирует полноту и непересечение списков идентификаторов, но **не статистическую независимость** наблюдений и не отсутствие всех утечек данных. Для этого нужны предпосылки об эксперименте. Размер областей, отсутствие пересечений траекторий и момент появления подписей определяет автор сцены.

## Галерея и научный статус

Эпизод 7 использует двенадцать явно заданных учебных чисел в `VALUES`, фиксированный диапазон `[-2,2]` и авторский порядок `[2,0,1]`. Четыре состояния: прочитать матрицу → выбрать R3 → провести её по свободной полосе → проверить прежнее значение R3,C2. Расстояния, дендрограмма и кластеризация не вычисляются.

Эпизод 8 использует ровно двенадцать учебных записей S1–S12. Четыре состояния: весь набор → резерв S9–S12 → построение S1–S4, неиспользуемые S5–S8 и прежний резерв → проверка на S9–S12. Новые данные не появляются. Подписи областей входят после того, как движущиеся объекты освободили их место. Ни модель, ни метрика качества не рассчитываются.

Оба эпизода имеют три построения, четыре состояния заметок и по два вопроса `qa` с объяснёнными ответами и источником чисел. Все величины синтетические; значения из старых статей и учебных наборов не перенесены.

## Происхождение приёмов

Перестановка постоянных ячеек и распределение наблюдений по ролям адаптированы из локальных курсовых реализаций. Текущие компоненты используют API `F/T/K`, явные данные и проверки допустимых перестановок и разбиений. Исходные данные статей, специальные модели и результаты курсовых работ не входят в галерею. История кода и границы прав — в [provenance.md](provenance.md).

## Проверки

`node tests/matrices-partitions.cjs` использует установленный в окружении `jsdom`. Проверяются входные данные, разреженные массивы, фиксированная шкала, биекции, сохранение DOM-идентичности, координаты прямых и обратных переходов, полнота разбиений, уникальность ролей и согласованность заметок/QA. Для каждого из шести построений выбирается 41 момент с тем же easing: все двенадцать основных объектов остаются внутри безопасной сцены 60…1220 × 147…610 и не перекрывают друг друга. Это проверка вычислений и SVG-геометрии, а не замена просмотра в браузере. После изменения шрифта повторно проверьте реальные рамки подписей в браузере, включая промежуточные кадры; расчётная геометрия не подтверждает новое отображение текста.
